# Roster UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build roster's SPA — every screen in the design handoff — transplanting an existing React codebase as the starting point, wiring the screens that have a backend to the live API and backing the rest with mocks until their endpoints exist.

**Scope:** frontend only. The backend has its own plan: [2026-08-01-roster-setup.md](2026-08-01-roster-setup.md). This plan assumes that one is complete.

**Architecture:** React 18 + Vite + Tailwind 4 SPA talking to `localhost`. React Query owns server state; React Router owns navigation; MSW owns the mock boundary. `app/` holds the shell, `modules/` holds feature slices, `components/ui/` holds design-system primitives, `lib/api/` holds the typed envelope client.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind 4, React Query v5, React Router v6, MSW v2, Vitest, Testing Library, pnpm.

**Design source of truth:** [`docs/design/README.md`](../../design/README.md) and the hi-fi canvas beside it. Exact tokens, dimensions, and per-screen specifications live there — this plan references sections rather than duplicating values, so there is one authority and no drift. **The hi-fi canvas is the visual authority; where this plan and the handoff disagree, the handoff wins.**

**Spec:** [`docs/specs/2026-08-01-roster-design.md`](../../specs/2026-08-01-roster-design.md) §6 covers the frontend, including the three deliberate deviations from the handoff.

## Global Constraints

Every task's requirements implicitly include this section.

- **pnpm only.** Never `npm` or `yarn`. All commands run from `projects/ui`.
- **TypeScript strict.** No `any`, no `@ts-ignore`. If a type is genuinely unknown, `unknown` plus a narrowing check.
- **`pnpm lint` (eslint + `tsc --noEmit`) and `pnpm test` must be green before any commit.**
- **Envelope:** every API response is `{success, data, error}`, plus `meta` for paginated collections. The client unwraps it; components never see the envelope.
- **Design tokens come from Tailwind config**, never hardcoded hex values in components. A literal `#7c6cf0` in a component is a defect.
- **Mock-first:** `VITE_USE_MOCKS=true` is the default and the whole app must run with no backend. `VITE_LIVE_API=true` proxies `/api` to `localhost:8000`.
- **Every screen must handle loading, empty, and error states.** A screen that only renders its happy path is incomplete.
- Tests use AAA structure with descriptive behaviour names, and query by role or label rather than test id where the accessible query works.
- Commit format `<type>: <description>`. No attribution trailers.
- The string `naaf` must not appear anywhere under `projects/ui` after Task 1.

## The live/mocked boundary

Roughly half the designed screens have no backend, and that is the single biggest source of confusion in this plan: a screen that looks finished may be entirely fixtures. **Task 4 makes this explicit and machine-checked** — do not let it drift.

| Screen | Data source | Backing API |
|---|---|---|
| Board, Issues List | **live** | `GET /projects`, `GET /work-items?project_id=` |
| Work Item Detail — Spec, Activity | **live** | `GET/PATCH /work-items/{id}`, `GET /runs/{id}/events` |
| Create Project, Create Work Item | **live** | `POST /projects`, `POST /work-items` |
| Agents, Agent Detail (read) | **live** | `GET /agents` |
| Agent Detail (rename, edit `AGENT.md`, model picker) | **mocked** | no write endpoints yet |
| Dashboard — agents panel, activity, token chart | **live** | `GET /runs`, `GET /runs/{id}/events` |
| Dashboard — budget, metric cards | **mocked** | no budget entity |
| Work Item Detail — Thread tab | **mocked** | no `Thread`/`Message` |
| Threads (global) | **mocked** | no `Thread`/`Message` |
| Work Item Detail — Attachments tab | **mocked** | no `Attachment` |
| MCP Servers, MCP Detail | **mocked** | no `McpServer` |
| Settings — Secrets | **mocked** | no `Secret` |

## Task 4: The API client and the live/mocked registry

This task exists to stop the plan's biggest risk: half the app is fixtures, and nothing stops a screen quietly staying mocked after its API arrives.

**Files:**
- Modify: `src/lib/api/client.ts`, `src/lib/api/queryKeys.ts`
- Create: `src/lib/api/dataSources.ts`, `src/lib/api/dataSources.test.ts`
- Create: `src/mocks/live-parity/`, `src/mocks/unbacked/`

**Interfaces:**
- Produces: `DATA_SOURCES` — a typed record mapping every screen to `"live"` or `"mocked"` with the reason; `useDataSource(screen)` for the dev-only badge.

- [ ] **Step 1: Write the failing test**

`src/lib/api/dataSources.test.ts`:

```ts
import { readdirSync } from "node:fs";
import { join } from "node:path";

import { describe, expect, it } from "vitest";

import { DATA_SOURCES } from "./dataSources";

describe("data source registry", () => {
  it("records a source for every screen", () => {
    const screens = Object.keys(DATA_SOURCES);

    expect(screens).toContain("board");
    expect(screens).toContain("threads");
    expect(screens).toContain("mcpServers");
  });

  it("requires a reason for every mocked screen", () => {
    for (const [screen, entry] of Object.entries(DATA_SOURCES)) {
      if (entry.source === "mocked") {
        expect(entry.reason, `${screen} is mocked without a reason`).toBeTruthy();
      }
    }
  });

  it("keeps mock handlers segregated by whether the API exists", () => {
    // A handler under unbacked/ for a screen marked live means the screen
    // regressed to fixtures, or the registry is lying. Both are defects.
    const unbacked = readdirSync(join(__dirname, "../../mocks/unbacked"));

    for (const file of unbacked) {
      const screen = file.replace(/\.ts$/, "");
      if (screen in DATA_SOURCES) {
        expect(DATA_SOURCES[screen].source).toBe("mocked");
      }
    }
  });
});
```

- [ ] **Step 2: Run and confirm it fails**

- [ ] **Step 3: Write the registry**

`src/lib/api/dataSources.ts` — transcribe the table in "The live/mocked boundary" above, one entry per screen:

```ts
export type DataSource = { source: "live" | "mocked"; reason?: string };

export const DATA_SOURCES: Record<string, DataSource> = {
  board: { source: "live" },
  issuesList: { source: "live" },
  workItemSpec: { source: "live" },
  workItemActivity: { source: "live" },
  createProject: { source: "live" },
  createWorkItem: { source: "live" },
  agents: { source: "live" },
  agentDetailWrites: { source: "mocked", reason: "no agent write endpoints yet" },
  dashboardActivity: { source: "live" },
  dashboardBudget: { source: "mocked", reason: "no budget entity in the backend plan" },
  workItemThread: { source: "mocked", reason: "no Thread/Message persistence yet" },
  threads: { source: "mocked", reason: "no Thread/Message persistence yet" },
  workItemAttachments: { source: "mocked", reason: "no Attachment persistence yet" },
  mcpServers: { source: "mocked", reason: "no McpServer persistence yet" },
  mcpServerDetail: { source: "mocked", reason: "no McpServer persistence yet" },
  settingsSecrets: { source: "mocked", reason: "no Secret persistence yet" },
};
```

Split the MSW handlers to match: `src/mocks/live-parity/` holds handlers that mirror a real endpoint (used only when `VITE_USE_MOCKS=true`), `src/mocks/unbacked/` holds handlers for endpoints that do not exist. Moving a screen to live means deleting its file from `unbacked/` — which the test above then requires the registry to reflect.

In `AppShell`, when `import.meta.env.DEV`, render a small corner badge showing the current screen's data source. Mocked screens must be visibly mocked while developing. It must not render in a production build — assert that with a test.

- `make dev` boots API and UI together; a project created in the UI lands on disk with its `.roster/` folder.
- Every screen in the handoff exists and handles loading, empty, and error states.
- **Every mocked screen is registered in `DATA_SOURCES` with a reason, visibly badged in dev, and its handlers live under `src/mocks/unbacked/`.** The count of entries there is the honest measure of how much of this app is real.
- No file under `projects/ui` contains the string `naaf`.

## Not in this plan

- Backend endpoints for `Thread`, `Message`, `McpServer`, `Secret`, `Attachment` — until those exist, those screens stay fixtures. Each one is a follow-up pairing a backend slice with un-mocking its screen.
- Agent write endpoints (rename, edit `AGENT.md`, model change).
- An end-to-end suite — deferred with the backend plan; revisit once these screens are stable, since that is what makes the journey meaningful.
- Electron packaging.
